# v0.2.0 보안 점검 — 2026-11-05

이 문서는 **0.2.0 점검 당시 상태**입니다. 후속 Qt6.11.3 교체·계정별 제한·릴리즈 보호·실제 업데이트 검증은 [v0.2.2 검증](RELEASE_VALIDATION_0.2.2.md)을 참고합니다. 아래 ‘미해결’ 표기를 현재 버전의 판정으로 사용하지 않습니다. 게시자 서명·공증 미적용과 모든 인증 이메일 허용 정책은 여전히 구분해야 합니다.

대상 소스 `c7a464dfed304e3838499019daa782c18757e862`, 공개 바이너리 v0.2.0. 코드 검토, 현재 PC의 접근 권한·listen 주소, 운영 서비스의 비인증 거부 응답, 합성 보안 회귀 및 공식 의존성 공지를 확인했다. 침투 시험 전체나 보안 인증을 완료했다는 뜻이 아니다. 원본 사용자 명단·토큰·키·비공개 URL은 보고서에 넣지 않는다.

## 판정과 우선순위

**취약점이 없다고 판정할 수 없다. Qt 보안 업데이트를 우선 처리해야 한다.** 이번 점검 범위에서 원격 인증 우회·서명되지 않은 자동 업데이트 실행을 재현하지는 않았다. 기능 검증 통과와 의존성 보안 공지 대조는 별도이며, 릴리즈 전 후자의 확인이 부족했다.

### 1. Qt 6.8.3 보안 수정 미반영 — 우선 보완

- 확실한 사실: 공개할 때 검증한 Windows 번들의 `Qt6Core.dll`·`Qt6Network.dll` FileVersion은 모두6.8.3.0이다. Mac CI도 SDK6.8.3을 명시해 설치한다. `src/core/Http.cpp`는 `QNetworkAccessManager`를 사용한다.
- [CVE-2026-76151 공식 공지](https://www.qt.io/blog/security-advisory-cve-2026-76151): 해당 버전 범위의64bit QtNetwork에 비정상 Cache-Control 헤더 처리로 인한 클라이언트 종료 위험이 있다. 공지의 영향은 서비스 거부이며, 이 항목을 정보 유출·원격 코드 실행으로 확대하지 않는다.
- [CVE-2026-105946 공식 공지](https://www.qt.io/blog/security-advisory-cve-2026-105946): 해당 버전 범위에서 NTLM 인증을 사용하는 경로는 메모리 읽기/종료 위험이 있다. 이 런처가 실제 NTLM 인증을 수행하는 공격 경로는 재현하지 않았다.
- [VectorImage 공지](https://www.qt.io/blog/security-advisory-qml-code-injection-in-vectorimage)의 버전 범위에도 해당하지만, 현재 QML 소스에서 VectorImage 사용을 찾지 못했다. 이 기능의 코드 삽입 취약점이 현재 앱에서 악용 가능하다고 판정하지 않는다.
- 조치: 해당 보안 수정이 포함된 지원 SDK로 교체하거나 공식 패치를 적용하고 Windows·ARM Mac·Intel Mac을 모두 다시 빌드·검증한다. Windows DLL만 교체하거나 이전 Mac 산출물을 재사용해 해결된 것으로 쓰지 않는다. 현재0.2.0의 이 항목은 **미해결**이다.

### 2. 최초 설치 파일의 OS 게시자 서명 없음 — 배포 신뢰 보완

실제 Windows Setup의 `Get-AuthenticodeSignature`는 `NotSigned`다. Mac은 ad hoc 무결성 검사는 통과했지만 Apple Developer ID·공증은 없다. 런처 내부의 P-256 피드·파일 해시 검증과 OS 게시자 인증은 서로 다른 보호다. 이미 신뢰해 설치한 런처의 자동 갱신 보호가 최초로 받은 임의 Setup의 출처까지 보증하지 않는다. 공식 다운로드·체크섬 안내를 유지하고 게시자 서명/공증을 별도로 추진한다.

### 3. GitHub main 보호 규칙 없음 — 저장소 권한 보완

읽기 전용 API 확인에서 `branches/main.protected=false`, `rules/branches/main`은0개였다. 이 상태는 침해 증거가 아니지만, 쓰기 권한 계정의 실수·침해가 main과 Pages에 바로 반영될 수 있다. PR 검토·필수 검사·force push/삭제 차단과 릴리즈 태그 보호를 권고한다. 이번 점검에서 저장소 권한/보호 정책을 변경하지 않았다. 계정/조직의2FA 강제 여부는 확인하지 않았다.

### 4. 모든 인증 이메일 허용 — 의도된 공개 범위

사용자가 지정한 정책은 이메일 일회용 코드로 인증한 모든 사람을 허용하는 방식이다. 이메일 소유 확인은 팀원·승인된 테스터 신원 보증과 다르다. 주소를 아는 외부인도 자신의 이메일로 인증해 게임을 받을 수 있다는 공개 플레이테스트 전제다. 미공개 게임을 특정 인원에게만 보이게 하려면 별도의 승인/초대·허용 대상 정책이 필요하다. 이번 점검에서는 실사용자의 신규 OTP와 Cloudflare 콘솔의 현재 전체 정책을 재검수하지 않았으며 허용 대상을 임의로 바꾸지 않았다.

### 5. 인증된 사용자별 다운로드 제한 없음 — 가용성 보완

origin은 연결40개·파일 처리12개의 전역 상한과 비밀번호 실패 제한을 둔다. 코드상 인증된 계정별 다운로드 동시 수/대역폭 할당은 없다. 인증 가능한 한 사용자의 반복 다운로드가 다른 테스터의 처리 용량을 차지할 수 있다. 계정별 동시 수·재시도 간격 제한을 검토한다. 운영 서버를 대상으로 부하 공격을 실행하지 않았으므로 장애 재현으로 기록하지 않는다.

## 한계와 다음 작업

이번 점검은 전체 퍼징·DDoS·공급망 침해·키 탈취·모든 의존성 CVE 조사·모든 OS 실기를 포괄하지 않는다. 관리 포트 직접 listen과 로컬 설정을 확인했지만, 원격 관리형 Tunnel의 전체 ingress 설정을 새로 조회한 것은 아니다. 인증 파일 권한은 다른 PC에도 자동으로 동일하다고 가정하지 않는다.

우선순위는 **Qt 보안 패치 포함 SDK로 전체 재빌드 → 저장소/태그 보호 → 최초 설치 파일 게시자 서명 → 계정별 다운로드 제한**이다. 특정 인원에게만 게임을 공개할지는 현재의 공개 테스트 정책과 별도로 결정한다. 이 문서는 보완 완료 기록이 아니며, 현재 릴리즈 파일을 수정하거나 새 릴리즈를 게시하지 않았다.
