# 기기별 이메일 로그인 유지

2026-11-05. 0.2.3 후보 구현과 검증 절차다. Google OAuth는 추가하지 않는다. 이메일 최초 인증 뒤 기기 로그인을 유지하며 로그아웃·운영자 회수·키 손상/분실·180일 미사용 정리 때 재인증한다. 현재 공개0.2.2와 운영 정책은 별도이며, 이 문서만으로 운영 활성화나 릴리즈 완료를 주장하지 않는다.

## 인증 경계

최초 이메일 확인은 기존 Cloudflare Access OTP와 서버의 JWT 서명·issuer·audience 검증을 유지한다. 검증된 이메일에 기기 공개키를 등록하고, 개인키는 현재 Windows 사용자 DPAPI 또는 macOS Keychain 기반 인증 암호화로 보호한다. 기기명·하드웨어 일련번호·IP 지문은 수집하지 않는다. 공개키와 무작위 등록 식별자는 개인정보 안내에 추가하고 최초 등록 전에 새 동의를 받는다.

기기 요청은 서버가 발급한 짧은 일회용 challenge에 P-256 서명한다. method·정확한 path·Range·버전/동의 헤더를 함께 묶고, 재사용·만료·다른 경로·다른 기기·회수된 키를 거절한다. 서버에는 개인키나 장기 bearer 비밀값을 저장하지 않는다. challenge와 동시 다운로드·등록 개수는 제한한다. 정상 기기 요청만 기존 이메일 기록의 최근 접근 시각을 갱신한다. 로그아웃·관리자 회수·개인정보 삭제·장기 미사용 정리의 관계를 명시하고 검사한다.

기기 API의 경로는 `/client-device/`로 분리하고 최초 등록은 기존 Access 보호 아래 별도 endpoint를 사용한다. 기존 catalog·package·`/downloads`·관리 서비스의 인증 경계를 변경하지 않는다. Cloudflare에는 이 새 경로에 대한 구체적인 정책 설정이 필요하다. origin의 기기 서명 검증과 회귀가 준비되기 전에 해당 경로를 공개하지 않는다. 인증 URL·명령행·로그에 개인키·토큰을 넣지 않으며 공개 GitHub 업데이트 요청에는 어떤 게임 인증도 전송하지 않는다.

## 확인할 사항

- 클라이언트 암호화 저장·복원·손상·다른 사용자 복호화 실패, 공개 요청으로 인증정보 유출 없음.
- 최초 인증·등록·기기 소유 증명·재시작 후 유지·복사된 bearer 값만으로 접속 불가.
- 일회용 challenge의 원자적 소비·재생/기한/변조·동시성·입력 크기와 저장 경로 제한.
- 로그아웃·회수·이메일 삭제·보관기간 정리 후 접근 거절. 운영자 관리 수단 제공.
- 자동 업데이트와 서명·해시·압축 경로·설치/삭제 소유 범위를 계속 검증한다. 감염된 OS나 같은 사용자 권한의 악성코드까지 완벽하게 차단한다고 주장하지 않는다.

## 구현된 프로토콜

| 경로 | 검증 |
| --- | --- |
| POST `/launcher-device/enroll` | 기존 Access 보호와 서버 JWT 검증,0.2.3 이상·개인정보 안내3 동의. 공개키만 등록하며 운영자 암호로 등록 불가 |
| POST `/client-device/challenge` | 등록ID에 대한60초 일회용 nonce. 기기8개·전체4096개·익명 작업량20회/초(burst48) 상한. 게임·이메일·토큰을 응답하지 않음 |
| GET/HEAD `/client-device/catalog.json`, `/client-device/packages/<sha>.zip` | nonce 소유·유효기간·원자적 소비, P-256 서명으로method/path/Range/앱버전/동의버전 결합. 계정별 다운로드2개 상한을 기존 이메일과 공유 |
| POST `/client-device/revoke` | 해당 기기의 일회용 서명으로 자기 접근 회수. 최소 버전/동의 변경 중에도 회수 가능 |

카탈로그와 ZIP의 정본 bytes·publisher 서명은 바꾸지 않는다. 클라이언트 전송 계층이 기기 요청에만 새 경로를 적용한다. GitHub/공개 사이트 요청에는 이메일 쿠키나 기기 증명을 전송하지 않는다. nonce 만료/서버 재시작은409로 구분해 새 nonce를1회 재시도하고, 저장소 오류503을 기기 회수401로 오인하지 않는다. 실제 회수·잘못된 키는 재인증 안내로 연결한다.

Windows 개인키는 현재 사용자 DPAPI, Mac은 iCloud 동기화하지 않는 Keychain 보관64바이트 키의 서로 다른 절반으로 AES-256-CBC 암호화와 HMAC-SHA256 인증을 적용한다. 무작위 IV·인증값 우선 확인·상수 시간 비교를 유지하며, P-256 개인키는 서명할 때만 복호화하고 임시 버퍼를 정리한다. 이는 하드웨어 보안 모듈이나 이미 침해된 OS에 대한 완전한 보호를 뜻하지 않는다.

암호화된 기기 정보는 사용자 프로필의 `settings.json`에 저장한다. 등록 중 연결이 끊기면 `pending-device-login.json`의 같은 암호화 키로 재시도해 중복 등록을 막고, 완료 후 정리한다. 다른 채널로 설정을 변경하면 기존 기기 인증을 전달하지 않는다. 서명·계정/경로·공개키 형식·암호화 무결성 오류를 검증 없이 통과시키지 않는다.

## 운영·회수

기기 API는 기존0.2.2 전역 정책과 별도로0.2.3/동의3을 요구하므로 기존 사용자 접속을 유지하면서 먼저 검증할 수 있다. 구형 앱의 동의1 요청이 이미 확인된 동의3 기록을 덮어쓰지 않는다. 새 릴리즈 공개·피드 확인 뒤에만 전체 최소 버전을 올린다.

운영 PC에서 다음 도구를 사용한다. 기본 목록은 이메일을 마스킹하고 공개키·개인키·토큰을 출력하지 않는다. `active`는 회수/보관기간 기준이며 실제 동접이나 게임 실행 상태가 아니다.

```powershell
./tools/Manage-TrustedDevices.ps1 -PrivateRoot .local/production-distribution
./tools/Manage-TrustedDevices.ps1 -Action Revoke -DeviceId '<목록의 정확한 ID>'
# 위 결과를 확인한 뒤 실제 회수:
./tools/Manage-TrustedDevices.ps1 -Action Revoke -DeviceId '<목록의 정확한 ID>' -Apply
```

기기 등록은 이메일당 활성10개·보관 중 등록32개, 전체10000개로 제한한다. 사용자 삭제·180일 정리는 연관 기기 기록도 정리한다. 기기 접근 회수는 새 요청부터 적용하며 이미 내려받은 파일을 원격 삭제하지 않는다. 이메일 계정 자체의 향후 재등록 차단은 별도 Access 정책이며 현재 모든 이메일 허용 정책과 혼동하지 않는다.

앱 로그아웃은 서버 회수를 요청하고 로컬 키·동의를 삭제한다. 오프라인이면 로컬 삭제를 진행하되 서버 회수 미확인 안내를 표시한다. 필요하면 운영자가 위 도구로 회수한다. 앱 업데이트/복구·재설치는 같은 프로필을 보존하므로 로그아웃 메뉴와 구분한다. Keychain 접근 거부·Windows 사용자/보호 저장소 변경·손상은 로그인 복구가 필요할 수 있다.

## 현재 검증과 한계

Windows 네이티브11개(실제 PE의CFG/ASLR/고엔트로피/DEP/스택 보호·app/system 전용 import 검색 포함), 실제품QML·암호화·기기 복원·로그아웃 및 실제 C++↔Python HTTP 등록/서명/이어받기/회수 검증을 수행했다. 서버 전체93개 회귀도 통과했다. 최종 결과와 새로운 소스별 Mac·설치기·공개 이후 결과는 릴리즈 검증 기록에 별도로 남긴다. 실제 사람의 신규 OTP·운영 경로 검사는 아직 이 합성 결과에 포함하지 않는다.

## 먼저 완료한 UI 변경

0.2.3 작업 브랜치에서 최초 업데이트 확인과 일상적인 확인을 분리했다. 주기/포커스 확인은 우측 하단 ‘버전 확인중’과0~3개 점으로 표시하며 새 버전 발견·실제 오류만 gate를 연다. 포커스 확인의 최소 간격은60초다. 파일 메뉴에 런처 설치 폴더를 추가하고 도움말 정보에 경로를 표시한다. 이메일 인증과 catalog 검증·저장이 끝난 뒤 창을 복원·활성화하며 OS가 포커스를 거절하면 작업표시줄/Dock의 기본 주의 표시를 사용한다.

Windows Qt6.11.3/MSVC2022의 관련 실제품 QML·암호화·상태 전환 및 기존 회귀10/10이44.74초에 통과했다. 처음의 show()가 최대화 복원 상태를 초기화한 회귀는 setVisible(true)로 고쳤다. 제한 sandbox의 TEMP/소켓 실패와 정상 권한의 결과를 구분했다. 실제 사람 OTP, 새 기기 인증 운영 경로, 양쪽 Mac·최종 릴리즈는 아직 이 결과에 포함하지 않는다.
