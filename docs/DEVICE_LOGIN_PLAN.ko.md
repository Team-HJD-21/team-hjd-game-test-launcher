# 기기별 이메일 로그인 유지 — 구현 계획

2026-11-05. Google OAuth 추가는 사용자 요청으로 보류했다. 이메일 인증 후 기기별 로그인을 유지하고, 로그아웃·운영자 회수로 접근을 끝내는 방향이다. 이 문서는 완료·배포 증거가 아니다.

## 인증 경계

최초 이메일 확인은 기존 Cloudflare Access OTP와 서버의 JWT 서명·issuer·audience 검증을 유지한다. 검증된 이메일에 기기 공개키를 등록하고, 개인키는 현재 Windows 사용자 DPAPI 또는 macOS Keychain 기반 인증 암호화로 보호한다. 기기명·하드웨어 일련번호·IP 지문은 수집하지 않는다. 공개키와 무작위 등록 식별자는 개인정보 안내에 추가하고 최초 등록 전에 새 동의를 받는다.

기기 요청은 서버가 발급한 짧은 일회용 challenge에 P-256 서명한다. method·정확한 path·Range·버전/동의 헤더를 함께 묶고, 재사용·만료·다른 경로·다른 기기·회수된 키를 거절한다. 서버에는 개인키나 장기 bearer 비밀값을 저장하지 않는다. challenge와 동시 다운로드·등록 개수는 제한한다. 정상 기기 요청만 기존 이메일 기록의 최근 접근 시각을 갱신한다. 로그아웃·관리자 회수·개인정보 삭제·장기 미사용 정리의 관계를 명시하고 검사한다.

기기 API의 경로는 `/client-device/`로 분리하고 최초 등록은 기존 Access 보호 아래 별도 endpoint를 사용한다. 기존 catalog·package·`/downloads`·관리 서비스의 인증 경계를 변경하지 않는다. Cloudflare에는 이 새 경로에 대한 구체적인 정책 설정이 필요하다. origin의 기기 서명 검증과 회귀가 준비되기 전에 해당 경로를 공개하지 않는다. 인증 URL·명령행·로그에 개인키·토큰을 넣지 않으며 공개 GitHub 업데이트 요청에는 어떤 게임 인증도 전송하지 않는다.

## 확인할 사항

- 클라이언트 암호화 저장·복원·손상·다른 사용자 복호화 실패, 공개 요청으로 인증정보 유출 없음.
- 최초 인증·등록·기기 소유 증명·재시작 후 유지·복사된 bearer 값만으로 접속 불가.
- 일회용 challenge의 원자적 소비·재생/기한/변조·동시성·입력 크기와 저장 경로 제한.
- 로그아웃·회수·이메일 삭제·보관기간 정리 후 접근 거절. 운영자 관리 수단 제공.
- 자동 업데이트와 서명·해시·압축 경로·설치/삭제 소유 범위를 계속 검증한다. 감염된 OS나 같은 사용자 권한의 악성코드까지 완벽하게 차단한다고 주장하지 않는다.

## 먼저 완료한 UI 변경

0.2.3 작업 브랜치에서 최초 업데이트 확인과 일상적인 확인을 분리했다. 주기/포커스 확인은 우측 하단 ‘버전 확인중’과0~3개 점으로 표시하며 새 버전 발견·실제 오류만 gate를 연다. 포커스 확인의 최소 간격은60초다. 파일 메뉴에 런처 설치 폴더를 추가하고 도움말 정보에 경로를 표시한다. 이메일 인증과 catalog 검증·저장이 끝난 뒤 창을 복원·활성화하며 OS가 포커스를 거절하면 작업표시줄/Dock의 기본 주의 표시를 사용한다.

Windows Qt6.11.3/MSVC2022의 관련 실제품 QML·암호화·상태 전환 및 기존 회귀10/10이44.74초에 통과했다. 처음의 show()가 최대화 복원 상태를 초기화한 회귀는 setVisible(true)로 고쳤다. 제한 sandbox의 TEMP/소켓 실패와 정상 권한의 결과를 구분했다. 실제 사람 OTP, 새 기기 인증 운영 경로, 양쪽 Mac·최종 릴리즈는 아직 이 결과에 포함하지 않는다.
